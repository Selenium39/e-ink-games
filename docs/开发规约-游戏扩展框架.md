# 开发规约：游戏扩展框架（games.e-ink.me）

> 版本：v1（2026-09-27）
> 性质：**所有游戏并行开发任务的唯一实现契约**。写代码的任务看不到规划对话，本文档必须自包含、无歧义；与《实施方案-games.e-ink.me.md》《调研报告-墨水屏游戏网站.md》不矛盾的条目为其**细化**，矛盾处仅限 §11「契约新增决策」所列，并以本文档为准。
> 首个实现：Sudoku。之后连续新增 10+ 个纯浏览器游戏，本文档的扩展性是硬指标：**新增一个游戏 = 复制模板 + 填 4 个文件 + 1 个文案文件，零路由改动、零注册表登记**。

---

## 0. 总原则

1. **游戏逻辑与 React 完全解耦**（继承实施方案 §二决策）：每个游戏 = `logic.ts`（纯函数状态转移）+ `render.ts`（DOM patch）。Next.js 只做壳页面与加载器。游戏代码构建为独立 IIFE，**不进 React 水合链路**。
2. **meta.json 驱动一切**：路由生成、分类页、sitemap、OG 图、每日挑战聚合，全部构建期从 `games/*/meta.json` glob 发现。**禁止任何手工维护的游戏列表**。
3. **墨水屏优先**：0 外部请求、无动画、无 hover、1-bit 状态、最小脏区更新（详见 §10）。
4. **纯函数优先**：`logic.ts` 零 DOM、零 React、零第三方依赖、零副作用（除 `_engine/rng` 注入的随机源）；跨游戏复用的能力一律下沉 `_engine/`。
5. **构建期失败优于运行期出错**：gzip 超预算、meta.json/content 校验不过、ES2016+ API 误用，一律 `npm run games:build` / CI 直接 fail。

## 1. 目录与文件契约

```
src/games/
├── _engine/                    # 公共模块（下划线开头，构建管线与 registry 忽略）
│   ├── storage.ts              # 三级降级存档（§4.1）
│   ├── rng.ts                  # 可种子化随机（§4.2）
│   ├── events.ts               # 极简事件（§4.3）
│   ├── state.ts                # 回合制状态机 + undo（§4.4）
│   └── global.d.ts             # window.EGames 类型声明
├── _template/                  # 新游戏模板目录（下划线开头，被忽略，不参与构建）
│   ├── logic.ts / render.ts / index.ts / meta.json   # 骨架 + 注释
├── sudoku/                     # 每个游戏目录，目录名 = slug（[a-z0-9-]+）
│   ├── logic.ts                # 纯函数游戏逻辑（零 DOM/React/第三方依赖）
│   ├── render.ts               # DOM patch 渲染层（只 import ./logic 与 _engine/*）
│   ├── index.ts                # ★ bundle 唯一入口（§3）
│   ├── meta.json               # 机器可读元数据（§2）
│   └── logic.test.ts           # （可选）纯函数单测
└── minesweeper/ …              # 后续游戏同构
```

硬性规则：

- 每个游戏目录**必须恰好包含** `logic.ts`、`render.ts`、`index.ts`、`meta.json`，缺一即不参与构建与页面生成（视为半成品，`games:build` 输出 warning）。
- **下划线 ` _ ` 开头的目录**（`_engine`、`_template`、未来 `_dev` 等）一律被 registry glob、esbuild 打包循环、页面生成**忽略**。规则统一为：glob `src/games/*/meta.json` 且排除首字符为 `_` 的目录。
- `render.ts` 与 `index.ts` 允许 import：`./logic`、`_engine/*`、`@marcomattes/epaper-components`（按需具名，见 §3.4）。**禁止 import react / next 任何模块**（esbuild 打包时若解析到 react 依赖即 fail）。
- `logic.ts` **禁止** import 本目录之外任何模块（含 `_engine` 中除 `rng` 外的部分——随机通过 `newGame` 参数注入或内部调用 `_engine/rng`，见 §5.1）。

> **契约新增决策 ①**：实施方案 §二目录树的每游戏仅列 `{logic.ts, render.ts, meta.json}`，本契约增加 **`index.ts` 作为 bundle 唯一入口**。理由：esbuild 需要单一入口文件；挂载/特性检测/全局注册逻辑（§3.3）需要独立于 render 的落点，避免每个游戏重写。

## 2. meta.json schema 与 registry

### 2.1 schema（类型定义在 `src/content/games/types.ts`，与 §8 共用）

```ts
export type GameCategory = 'puzzle' | 'word' | 'board' | 'logic' | 'daily';

/** 封闭词表；新增值须同步改本联合类型（一行），build 校验报未知值 */
export type EngineFeature = 'grid' | 'keypad' | 'timer' | 'undo' | 'notes' | 'hints' | 'daily';

export interface GameMeta {
  slug: string;                    // = 目录名，^[a-z0-9-]+$，全语言统一（hreflang 干净）
  title: string;                   // 英文游戏名，如 "Sudoku"（站点内通用标识，非 SEO title）
  category: GameCategory;
  difficulties: string[];          // 如 ["easy","medium","hard","expert"]；无难度游戏给 ["standard"]
  engineFeatures: EngineFeature[];
  seeded: boolean;                 // true = 支持每日种子（§4.2），纳入 /daily 聚合（P2）
  seo?: {                          // 预留：构建期 SEO 管线可选读取
    keywordsHint?: string[];       // 如 ["sudoku for kindle", "e ink sudoku"]
    videoGameGenre?: string;       // VideoGame JSON-LD 的 genre，如 "Puzzle"
  };
}
```

示例 `sudoku/meta.json`：

```json
{
  "slug": "sudoku",
  "title": "Sudoku",
  "category": "puzzle",
  "difficulties": ["easy", "medium", "hard", "expert"],
  "engineFeatures": ["grid", "keypad", "timer", "undo", "notes"],
  "seeded": true,
  "seo": { "keywordsHint": ["sudoku for kindle", "e ink sudoku"], "videoGameGenre": "Puzzle" }
}
```

### 2.2 registry（构建期生成，禁止手改）

- 脚本 `scripts/build-games.mjs`（`npm run games:build`）执行：
  1. glob `src/games/*/meta.json`（排除 `_` 开头目录）→ 逐个 JSON parse + zod 校验（slug 与目录名一致性、`difficulties`/`engineFeatures` 词表合法性、slug 唯一性）；
  2. esbuild 打包每个游戏（§3）；
  3. gzip 尺寸断言（§3.5）；
  4. 生成 `src/lib/games.registry.ts`（实施方案目录树中已有此文件名）。
- 生成物头部固定注释 `// @generated by scripts/build-games.mjs — DO NOT EDIT`。内容：按 slug 字母序导出的 `GameMeta[]` 及 `getGame(slug)`、`gamesByCategory()` 辅助。
- **路由、分类页、sitemap、OG 图、每日聚合页的 `generateStaticParams` / 生成循环全部 import 此 registry**。目录无 `meta.json` → 不打包、不出页面、不进 sitemap。

> **契约新增决策 ②**：实施方案目录树将 `games.registry.ts` 描述为"游戏元数据注册表"，未指明来源；本契约明确其为**构建期生成物**，并规定 per-game 文案不在 registry 内（文案归 §8 的 content 目录，registry 只承载 meta.json 数据 + 各 locale 已回退合并后的 SEO title/description 索引）。

## 3. 游戏 bundle 契约

### 3.1 构建参数

每个游戏 `index.ts` 经 esbuild 打包为 `public/games/{slug}.js`：

```
entry:      src/games/{slug}/index.ts
outfile:    public/games/{slug}.js
bundle:     true   minify: true   sourcemap: false
format:     iife   target: es2015   legalComments: none
```

- 产物通过**普通 `<script defer>`** 加载（**非 `type=module`**，兼容老 Kindle WebKit，继承实施方案 §4.1/§七.1）。
- `target: es2015` 只转译**语法**（`?.`、`??`、class fields 等可用），**不 polyfill API**。运行时 API 白名单/黑名单见 §10。

### 3.2 IIFE 首行特性检测（三层增强第 3 层）

bundle 执行的最初步骤（esbuild `banner` 注入或 `index.ts` 首条语句，实现任选，行为必须一致）：

```js
// 伪代码：检测失败路径
if (!(window.customElements && typeof window.customElements.define === 'function')) {
  var root = document.getElementById('game-root');
  if (root) root.textContent = root.getAttribute('data-fallback') ||
    'This game needs a newer browser.';   // 英文兜底
  return;                                  // 终止：不注册、不挂载、不抛未捕获错误
}
```

> **契约新增决策 ③**：降级文案的**本地化**由壳层预置——GameShell 在 `#game-root` 上输出 `data-fallback`（当前 locale 文案，§7.1）；bundle 失败时优先读该属性，容器为空才写英文兜底。理由：16 语言一句文案内联进 bundle 会白吃每个游戏 ~1KB 预算。

### 3.3 全局注册与自挂载（检测通过后）

```ts
declare global {
  interface Window {
    EGames: Record<string, { mount: (root: HTMLElement, opts?: MountOpts) => void }>;
  }
}
export interface MountOpts { seed?: number }   // 预留：外部注入每日种子等
```

行为契约（`index.ts` 模板已实现，游戏开发者只需换 `slug` 与 `mount` 实现）：

1. `window.EGames = window.EGames || {}`；注册 `window.EGames['{slug}'] = { mount }`。
2. **自挂载**：扫 `document.querySelectorAll('#game-root[data-game="{slug}"]')`，对每个容器调 `mount(el)`。`defer` 保证 DOM 已就绪；若 `document.readyState === 'loading'`（异常注入时序）则等 `DOMContentLoaded`。
3. `mount` 必须**幂等**：`root.dataset.mounted === '1'` 时先清理自身再重建（挂载后置 `data-mounted="1"`）。
4. 同一页面**至多一个** `#game-root`（id 全页唯一，壳层保证）。
5. 挂载的 `opts` 缺省为 `undefined`：seeded 游戏自行用 `_engine/rng.seedFromDate` 取当日种子（§5.2）。

### 3.4 依赖与样式

- `@marcomattes/epaper-components` **只具名 import 实际用到的组件入口，禁止全量入口或 `import *`**，由 esbuild tree-shake 进 bundle；包内具体导出路径以锁定版本的包 README 为准（0.x，包版本锁死）。
- 游戏私有 CSS：不单独出 css 文件（少一个请求）。`index.ts` 挂载时注入一次性 `<style id="game-{slug}-css">`，min 后 **≤2KB**，颜色只用 `--ink-*` token。

> **契约新增决策 ④**：私有样式采用运行时 `<style>` 注入而非 esbuild css entry。理由：游戏区内容本就 JS 挂载后才出现，无 FOUC 可言；省一个 HTTP 请求（墨水屏设备建连成本高）。

### 3.5 尺寸预算

- 每游戏产物 **gzip ≤ 15KB**（继承实施方案 §4.4）。`games:build` 计算实际 gzip 字节数，超限即 fail 并打印各游戏尺寸表。Sudoku 首打样须预留 ≥3KB 余量作为后续游戏基准参照。

## 4. `_engine` 公共模块（四模块 TS 签名）

### 4.1 `storage.ts` — localStorage → cookie → 内存 三级降级

```ts
export type StorageTier = 'local' | 'cookie' | 'memory';

export const SCHEMA_VERSION = 1;      // 存档格式版本：破坏性变更时 +1，旧档自动作废
export const NAMESPACE = 'egames';    // 站点命名空间前缀

/** 实际落盘记录结构（对调用方透明，load 时自动解包） */
export interface StorageRecord<T> { v: number; at: number; data: T }

/**
 * 依次尝试 localStorage → cookie → 内存；返回实际达成层级，全部失败返回 null。
 * 任何异常（隐私模式、配额满、禁 cookie）静默降级，**绝不抛错**。
 * cookie 层单条有效载荷 >3.5KB 时视为失败（4KB 上限留余量），继续降级。
 */
export function save<T>(slug: string, key: string, data: T): StorageTier | null;

/** 按 local→cookie→memory 顺序读；无档 / v 不匹配 SCHEMA_VERSION / JSON 损坏 → null（并清掉坏档） */
export function load<T>(slug: string, key: string): T | null;

/** 三层全部移除；不存在视为成功 */
export function remove(slug: string, key: string): void;

/** 当前最高可用层级；null = 三层全禁（极端隐私模式，游戏应隐藏"继续游戏"入口） */
export function tier(): StorageTier | null;
```

- 物理 key 统一为 `` `${NAMESPACE}:${slug}:${key}` ``（cookie 同名）。**游戏禁止裸用 `localStorage` / `document.cookie`**（§10）。
- **存档 key 命名约定**（跨游戏统一，便于设置页/统计页枚举）：

| key | 用途 |
|---|---|
| `save1` | 主存档槽（单存档） |
| `daily:{YYYY-MM-DD}`（UTC） | 每日挑战当日结果 |
| `stats` | 累计统计（局数/胜场/最佳时间） |

> **契约新增决策 ⑤**：存档内容**不含 solution 与 undo 栈**。理由：防用户翻档作弊；undo 栈 100 步全量序列化体积不可控（刷新后 undo 历史丢失，业界惯例可接受）。undo 栈只存内存（§4.4）。

### 4.2 `rng.ts` — 可种子化随机（禁裸 `Math.random`，§10）

```ts
export type Seed = number; // uint32

/** mulberry32。同 seed 产出同序列（跨设备、跨版本一致——每日挑战的正确性基础） */
export function createRng(seed: Seed): Rng;

export interface Rng {
  next(): number;                     // [0,1)，32bit 精度
  int(maxExclusive: number): number;  // [0, maxExclusive)，floor(next()*max)；max≤1e6 偏差可忽略
  pick<T>(items: readonly T[]): T;    // items 为空属编程错误，实现可 throw
  shuffle<T>(items: readonly T[]): T[]; // Fisher-Yates，返回新数组，不改入参（纯函数要求）
}

/** 冻结算法：UTC 日期 → "YYYY-MM-DD" → 'daily:'+iso → FNV-1a 32bit */
export function seedFromDate(d: Date): Seed;

/** 字符串种子（扩展预留）。FNV-1a：h=0x811c9dc5; h=Math.imul(h^c,0x01000193); return h>>>0 */
export function hashSeed(s: string): Seed;
```

> **契约新增决策 ⑥**：`seedFromDate` 与 `hashSeed` 的算法**上线即冻结**，任何改动会破坏"同一天全设备同一谜题"。实现必须逐字符对照上方 FNV-1a 公式，并配单测固定向量（模板测试文件给出）。

### 4.3 `events.ts` — 极简事件

```ts
export type Handler<T = unknown> = (payload: T) => void;

export interface Emitter<Events extends Record<string, unknown>> {
  on<K extends keyof Events & string>(event: K, fn: Handler<Events[K]>): () => void; // 返回 off 函数
  off<K extends keyof Events & string>(event: K, fn: Handler<Events[K]>): void;
  emit<K extends keyof Events & string>(event: K, payload: Events[K]): void;
}

export function createEmitter<Events extends Record<string, unknown>>(): Emitter<Events>;
```

行为钉死：`emit` **同步**调用、按注册顺序；emit 时对 handler 列表取快照遍历（回调内 off/emit 不跳变、不死递归）；单个 handler 抛错被吞掉且不中断后续 handler（墨水屏设备无 console，错误静默）。`logic.ts` **不使用** events（纯函数无副作用）；events 供 render 层内部解耦用（如输入模块 → 棋盘模块）。

### 4.4 `state.ts` — 回合制通用状态机

```ts
export const UNDO_LIMIT_DEFAULT = 100;

/** S 必须是纯数据（JSON-serializable，无函数/类实例/undefined），否则 serialize 结果不合法 */
export interface Serialized<S> { v: number; current: S }   // 存档只含当前态（决策⑤：不含 undo 栈）

export interface StateMachine<S> {
  get(): S;                          // 当前状态（引用不变直到下次 commit/replace/undo）
  commit(next: S): void;             // current 入 undo 栈后替换为 next；栈满丢最旧
  replace(next: S): void;            // 替换且**不入** undo 栈（新开局/载入存档用）
  undo(): S | null;                  // 回退一步并返回；栈空返回 null（不抛错）
  canUndo(): boolean;  undoDepth(): number;
  serialize(): Serialized<S>;
  deserialize(data: Serialized<S>): boolean; // v 不匹配或结构非法 → false 且状态不变
  onChange(fn: (s: S) => void): () => void;  // commit/replace/undo 后触发（render 订阅入口）
}

export function createState<S>(initial: S, opts?: { undoLimit?: number }): StateMachine<S>;
```

状态更新为**不可变风格**（`commit(newS)` 传新对象），render 依赖 `onChange` 做最小脏区 diff（§6）。

## 5. 游戏逻辑契约（Sudoku 为范本）

### 5.1 通用规则

- `logic.ts`：纯函数、零 DOM、零 React、**零第三方依赖**；除 `_engine/rng` 外禁止 import 任何模块。所有状态转移函数**不可变**：返回新 state，不改入参。
- 参数非法（数组长度≠81、越界 r/c、非法难度）属于编程错误：实现应 `throw` 让开发期暴露；render 层负责不传非法值。
- 所有生成/打乱内部随机**只能**来自 `createRng`；同 `seed` 必须产出同谜题。

### 5.2 Sudoku API 签名

```ts
export type Cell = number;              // 0=空，1-9
export type Grid = number[];            // 长度 81，行优先：idx = r*9 + c
export type Difficulty = 'easy' | 'medium' | 'hard' | 'expert';

export interface GameState {
  difficulty: Difficulty;
  seed: number | null;                  // null = 随机组局（非每日/非固定种子）
  givens: boolean[];                    // 81；true = 题面给定格（不可修改）
  values: Grid;                         // 81；当前盘面（givens 格恒等于题面数字）
  notes: number[];                      // 81；铅笔标记 bitmask，bit(v-1)=1 表示标了数字 v
}

export interface NewGameResult {
  puzzle: Grid;                         // 题面（给定格数字，其余 0）
  solution: Grid;                       // 唯一解
  givens: boolean[];                    // true=给定格（render 用此区分样式；语义 ≠ puzzle 的副本）
  state: GameState;                     // 初始 state（免去 render 手工拼装）
}

export function newGame(opts: { difficulty: Difficulty; seed?: number }): NewGameResult;
// 唯一随机源：createRng(opts.seed ?? (Date.now() >>> 0))。
// 难度 → 给定数目标（唯一解约束，允许 ±2 容差）：easy 38-40 / medium 30-32 / hard 25-27 / expert 22-24。
// 生成预算：真机 ≤1s（目标 <300ms）；挖洞必须维持唯一解（解计数 ≤1 校验）。

export function solve(grid: Grid): Grid | null;            // 求解任意 81 格盘面；无解 → null
export function applyMove(state: GameState, r: number, c: number, v: number): GameState;
// v ∈ 1-9；对 givens 格为 no-op（返回原引用）；同值重填亦 no-op；否则写入并清除该格 notes
export function clearCell(state: GameState, r: number, c: number): GameState;
// 清玩家格数字+notes；givens 格 no-op
export function toggleNote(state: GameState, r: number, c: number, v: number): GameState;
// 铅笔标记翻转；givens 格或该格已有数字时 no-op
export function getCandidates(state: GameState, r: number, c: number): number[];
// 该空格按当前盘面 rules 可填的数字，升序 1-9（用于提示与自动笔记）
export function checkErrors(state: GameState): number[];
// 返回与数独规则冲突（同行/列/宫重复）的格子 idx 列表，含冲突双方；不含 notes
export function isSolved(state: GameState): boolean;       // 81 格非空且行/列/宫各恰含 1-9
export function serialize(state: GameState): string;       // JSON 字符串（存档载荷，不含 solution）
export function deserialize(raw: string): GameState | null; // 非法/缺字段 → null
```

- `checkErrors` 采用**规则冲突**语义（不对照 solution 标错）：无需存 solution，存档天然防翻答案；与主流数独产品行为一致。
- 存档组装（`index.ts` 职责）：`storage.save('sudoku', 'save1', { s: logic.serialize(state), sec: seconds })`；`seconds` 为 render 层计时（§6.3），**不属于 GameState**。

### 5.3 render 与 logic 的边界

`render.ts` **只通过 §5.2 导出函数**读写游戏状态：禁止在 render 里重写规则判断（如自己判行列冲突）。render 允许维护纯 UI 状态（计时、铅笔模式开关、选中格），但任何"这步是否合法/是否赢了"的判断必须调 logic。

## 6. render 层契约

- **最小脏区更新**：订阅 `state.ts` 的 `onChange`，diff 前后 state，仅改受影响格子（示例见 §10）。**禁止** `innerHTML` 全量重绘（触发墨水屏整屏刷新，违背 epaper-components 的 patch 策略）。数据变化只改 `textContent` + `classList`。
- 交互 DOM 由 render 全权创建与持有；React/壳层不操作 `#game-root` 内部。
- 计时器（`engineFeatures` 含 `timer` 时）：`setInterval` 1s 自持，`visibilitychange`/挂载时对齐；**不写入 logic state**，随存档存 `sec` 字段。
- 输入：`click` + `keydown`（数字键/方向键/退格）按需绑定；**禁止依赖 Pointer Events**（老 WebKit 缺失），触控目标 ≥44px（§10）。

## 7. React 壳契约

### 7.1 `GameShell.tsx`（唯一 `'use client'` 组件）

```tsx
export interface GameShellProps { slug: string }
```

职责（仅此三项）：输出 `<div id="game-root" data-game={slug} data-fallback={本地化降级文案}>`（内含 `<noscript>` + 静态降级文案段落）；注入 `<script defer src="/games/{slug}.js">`（实现方式不锁，最终 HTML 必须是普通 defer script 且不阻塞首屏）。SSG 时 `data-fallback` 文案从 §8 文案取当前语言。

### 7.2 `GameFrame.tsx`（server component，禁止 `'use client'`）

```tsx
export interface GameFrameProps {
  children: React.ReactNode;   // 棋盘/游戏区——页面组合时放入 <GameShell slug=… />
  sidebar?: React.ReactNode;   // 可选：SSG 静态侧栏（设备提示卡等，无交互）
  promo?: React.ReactNode;     // 导流位（SSG 静态，无 JS 可见，§8 cta 字段渲染于此）
}
```

> **契约新增决策 ⑦**：交互控件（难度选择、undo、键盘等）**不作为 GameFrame 的 React slots**，全部由游戏 render.ts 创建。理由：React 与 vanilla 双写同一批控件会导致事件绑定与状态所有权冲突；且无 JS 环境下假按钮对用户是误导、对 SEO 无益。GameFrame 只做三区布局 + 静态导流位。

### 7.3 内容层隔离（继承实施方案 §4.2 三层增强第 1 层）

- 页面 SEO 正文（h1/tagline/howToPlay/deviceTable/whyEInk/FAQ/related 内链）由 **server component 直接输出静态 HTML**，**禁 JS 可完整阅读**（原生 `<details>` 允许，其余折叠禁用）。
- 双向禁令：内容层组件**禁止 import** `src/games/**`；壳组件（GameShell/GameFrame）**禁止承载**上述 SEO 正文。

页面组合范式：

```tsx
<GameFrame promo={<PromoCard cta={content.cta} />}>
  <GameShell slug="sudoku" />
</GameFrame>
```

## 8. 内容与文案契约

### 8.1 文件与回退

- 路径：`src/content/games/{slug}/{locale}.json`（`en.json` 为 source of truth，字段必须齐全）。
- 构建（并入 `games:build`）：以 en.json 为基底对其他 locale 做**字段级合并**（该 locale 缺的字段用 en 补）；再经 zod 校验合并结果，fail 即构建失败。语言可增量上线（实施方案 §七.3 的 8 语言首发预案直接兼容）。
- `games.common` 公共词（按钮"New Game/Undo"、设备表 status 展示词等）在 `src/lib/i18n/`，**不在**每游戏 JSON 重复。

### 8.2 字段清单（类型同在 `src/content/games/types.ts`）

```ts
export interface DeviceRow { device: string; status: 'yes' | 'limited' | 'no' } // 展示词由 games.common 映射
export interface FaqItem { q: string; a: string }

export interface GameContent {
  meta: { title: string; description: string }; // SEO <title> 与 meta description（≤160 chars）
  h1: string;                                   // 模板："{Game} for Kindle & E-Ink — Free, No Download"
  tagline: string;                              // 一句话价值主张，含设备词
  howToPlay: { steps: string[] };               // ≥4 步；en 合计 ≥150 词
  deviceTable: { rows: DeviceRow[] };           // ≥5 行（Paperwhite/Scribe/Colorsoft/BOOX/Kobo/…）
  whyEInk: string;                              // 50±20 词，无闪烁设计叙事
  faq: FaqItem[];                               // 恰 4 条（Free?/My device?/Jailbreak?/Offline?）→ FAQPage JSON-LD
  cta: { label: string; href: string };         // href 域名白名单：e-ink.me / news.e-ink.me / games.e-ink.me
  related: string[];                            // 3-5 个 slug，构建期校验须存在于 registry
}
```

### 8.3 消费方

`/games/[slug]/page.tsx` 的 `generateMetadata`、FAQPage/VideoGame JSON-LD、设备表、FAQ 区块、GameFrame promo 位，全部读本契约文件（经 registry 索引定位），任何一处的文案不允许硬编码在组件里。

## 10. 每游戏硬约束清单（PR 自检表）

| # | 约束 | 校验点 |
|---|---|---|
| 1 | 产物 gzip ≤15KB，私有 CSS min ≤2KB | `games:build` 断言 |
| 2 | 禁 CSS animation/transition/hover | 游戏私有样式无 `@keyframes`/`transition:`/`:hover`（epaper tokens 已全局禁，不得绕过） |
| 3 | 0 外部请求：无外部字体、无外部图片；图标仅内联 SVG | 产物与运行时均无跨域 URL |
| 4 | 最小脏区更新：禁 `innerHTML` 全量重绘 | 只 patch `textContent`/`classList`/局部属性 |
| 5 | 1-bit 状态表达：选中=3px 粗边框，错误=黑底白字反转，给定=实心黑字 vs 玩家=描边；**禁 opacity/灰阶/彩色表达状态** | 对照 epaper 设计规范 |
| 6 | 存档必须走 `_engine/storage`；随机必须走 `_engine/rng` | 全文搜索无裸 `localStorage`/`document.cookie`/`Math.random` |
| 7 | 触控目标 ≥44×44 CSS px | `e-keypad` 默认满足；自绘控件自查 |
| 8 | ES2015 语法 + API 黑名单（target 不补 API）：禁 `Array.flat/flatMap`、`Object.fromEntries/entries/values`、`String.replaceAll/padStart/trimStart`、`globalThis`、`structuredClone`、`Promise.allSettled/any`、`Element.animate`、Pointer Events、`closest/replaceWith/after` 等 | `games:build` 静态扫描（黑名单正则）+ 真机冒烟 |
| 9 | 非 module：普通 `<script defer>` IIFE | `games:build` 检查产物无 `import`/`export` 残留 |
| 10 | 特性检测失败可优雅降级：不抛未捕获错误、壳层内容不受影响 | 禁 JS / 模拟无 customElements 各测一次 |

```ts
// ✅ 单格 patch（EPDC 部分刷新）
cellEls[idx].textContent = v ? String(v) : '';

// ❌ 全量重绘（整屏刷新，墨水屏体验灾难）

```

## 11. 契约新增决策汇总（对实施方案的全部补充）

| # | 决策 | 理由 |
|---|---|---|
| ① | 每游戏增加 `index.ts` 作为 bundle 唯一入口 | esbuild 需单一入口；挂载/检测/注册逻辑需独立落点 |
| ② | `games.registry.ts` 为构建期生成物，禁手改 | 实施方案未指明来源；杜绝手工列表腐化 |
| ③ | 降级文案本地化：壳层 `data-fallback` 预置，bundle 优先读 | 16 语言内联每游戏白吃 ~1KB 预算 |
| ④ | 私有 CSS 运行时 `<style>` 注入，不出 css 文件 | 省一个 HTTP 请求；游戏区本就 JS 后出现，无 FOUC |
| ⑤ | 存档不含 solution 与 undo 栈 | 防翻档作弊；undo 全量序列化体积不可控 |
| ⑥ | 每日种子算法（seedFromDate/hashSeed）上线即冻结并配固定向量单测 | 改动破坏"同日全设备同谜题" |
| ⑦ | 交互控件归 render.ts，GameFrame 不提供交互 slots | 避免 React/vanilla 双写冲突；无 JS 不出假按钮 |
| ⑧ | per-game 文案放 `content/games/{slug}/{locale}.json`（实施方案树原列于 `lib/i18n/`） | 文案与游戏同目录、按游戏并行开发；`lib/i18n` 仅存 games.common 公共词 |
| ⑨ | ES2016+ **API** 黑名单清单（§10.8） | es2015 target 只转语法不补 API，老 Kindle WebKit 必踩 |
